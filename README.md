## Problem
Every Steam review has a binary label chosen by its author - Recommended or Not recommended - and free text. The project builds a model that predicts the recommendation from the text and explains which words signal a negative review. Reviewer attributes known at the moment of writing are tested as a secondary input. Such a model lets developers find negative feedback in large volumes of reviews and can be transferred to unlabelled feedback (forums, social media, support tickets).

Research questions and hypotheses:

RQ1: Can the review text alone predict the recommendation significantly better than a majority-class baseline? (answered in notebook 04)

H1: Players who do not recommend a game had less playtime at the moment of the review. (notebook 02)

H2: Negative reviews are longer than positive ones. (notebook 02)

H3: The recommendation rate differs for reviews written during early access and for free copies. (notebook 02)

## Dataset

Steam Reviews Dataset 2021: https://www.kaggle.com/datasets/najzeko/steam-reviews-2021

~21.7 million reviews, 23 columns, 300+ games, collected from the Steam API in January 2021, licence GPL-2.

The project uses a reproducible 2% random sample of the English reviews (192,543 rows; 189,072 after cleaning), split 70/15/15 into train / validation / test with stratification.

## Setup
Python 3.12 or newer (required by numpy 2.5 and scipy 1.18).

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### Download the data
Option A - Kaggle CLI (needs an API token: Kaggle -> Settings -> API -> Create New Token; put `kaggle.json` into `~/.kaggle/` on macOS/Linux or `%USERPROFILE%\.kaggle\` on Windows):

```bash
kaggle datasets download -d najzeko/steam-reviews-2021 -p data/raw --unzip
```

Option B - manually: download the archive from the Kaggle page, unzip it and put `steam_reviews.csv` into `data/raw/` (create the `raw` folder inside `data/` if it does not exist).

The expected path is `data/raw/steam_reviews.csv`.

## Run order
1. `notebooks/01_problem_dataset_preprocessing.ipynb` - Kernel -> Restart & Run All.
 The first run reads the 8 GB file once (~10-20 min) and caches the sample in `data/interim/`; later runs take seconds.
 Outputs: `data/processed/{train,val,test}.parquet`, `models/preprocessor_tabular.joblib`, `reports/figures/01-06*.png`, `reports/tables/*.csv`.
2. `notebooks/02_eda.ipynb` - exploratory data analysis on the training set (~1-3 min).
 Outputs: `reports/figures/07-17*.png`, `reports/tables/eda_*.csv` (summary statistics, correlations, statistical tests, conclusions).
3. `notebooks/03_feature_engineering.ipynb` - new features, feature selection (filters, RFECV, chi²), PCA / TruncatedSVD, final feature pipeline (~5-15 min).
 Outputs: `data/processed/{train,val,test}_features.parquet`, `models/feature_pipeline.joblib`, `models/feature_config.json`, `reports/figures/18-28*.png`, `reports/tables/fe_*.csv`.
4. `notebooks/04_text_mining.ipynb` - text preprocessing, 8 Bag-of-Words / TF-IDF variants, cosine similarity, 4 classifiers + majority baseline, hyper-parameter and threshold tuning, overfitting check (validation and learning curves), single test-set evaluation with bootstrap confidence intervals, word weights, error analysis (~20-35 min).
 Outputs: `models/D_final_text_model.joblib` (vectorizer + model + threshold), `reports/figures/D01-D13*.png`, `reports/tables/D_*.csv`, `reports/tables/D_summary.txt` (final conclusions and the answer to RQ1).

Each notebook needs the outputs of the previous ones; run them in this order. Notebook 04 needs `*_features.parquet` from notebook 03 and `preprocessor_tabular.joblib` from notebook 01.

All random operations use `random_state = 42`, so every run produces the same sample, the same split and the same models.

Evaluation protocol: everything learned (vocabulary, IDF weights, models) is fitted on train; every choice (features, representation, hyper-parameters, model, threshold) is made on validation; the test set is used once, at the end of notebook 04.

## Results
See `reports/tables/D_summary.txt`, produced by the last cell of notebook 04: final model, test metrics with 95% confidence intervals, answer to RQ1, main error patterns. Limitations and future improvements are listed at the end of notebook 04.
